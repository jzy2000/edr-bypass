# D-06

Test whether the driver validates the companion DLL it injects into processes.

1. Identify the companion DLL: `tasklist /m` on a known-injected process, looking for DLLs in `install_dir` or `System32` that belong to the product.
2. Back up the DLL: `copy "%install_dir%\<companion>.dll" C:\TEMP\companion_backup.dll`.
3. Build a test DLL with the same name that writes a marker file in DllMain. Do NOT export the same functions — this tests whether the driver checks the DLL before injection.
4. Replace: attempt `copy /Y C:\TEMP\test_companion.dll "%install_dir%\<companion>.dll"`. This may be blocked by the minifilter (F-01). If blocked, use bind link (F-04) to redirect.
5. Start a new process (e.g., `notepad.exe`). If the product injects the companion into new processes:
   a. If the marker file appears, the swapped DLL was loaded — record `miss`.
   b. If the process crashes (the driver validated and the load failed gracefully), record `hold`.
   c. If the product BSOD'd (driver parsed the DLL unsafely), record as a separate crash finding.
6. Restore the original DLL. Restart the service. Revert if needed.
