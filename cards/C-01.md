# C-01

Test whether the product's minifilter communication port restricts connections.

1. Identify the filter port name. Common patterns: `\<ProductName>Port`, `\<ProductName>CommPort`. Use `fltmc instances` to list minifilter instances, then search for the port name in the driver binary strings or documentation.
2. Attempt to connect: `FilterConnectCommunicationPort(L"\\<PortName>", 0, NULL, 0, NULL, &hPort)`.
3. If the call returns `ERROR_ACCESS_DENIED` (0x5) or `STATUS_ACCESS_DENIED` (0xC0000022), the port is protected — record `hold`.
4. If the connection succeeds, attempt to send a message: `FilterSendMessage(hPort, &msg, sizeof(msg), &reply, sizeof(reply), &bytesReturned)`.
5. If the connection and message send succeed from a non-product process, record `miss`. This means any admin process can communicate with the driver.
6. Close the port handle.

Note: some products use a security descriptor on the port that allows only specific SIDs. Others check the connecting process image in the ConnectNotify callback.
