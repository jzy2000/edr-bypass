# D-01

Test whether the product is vulnerable to DLL search-order hijacking.

1. Use Process Monitor or `tasklist /m` to identify DLLs the product process loads. Alternatively, start the product under ProcMon and filter for `NAME NOT FOUND` results on `CreateFile` for `.dll` paths. Each NAME NOT FOUND in the product's directory or `System32` is a candidate.
2. Create a minimal test DLL (`DllMain` writes a marker file to `%TEMP%\dll_hijack_proof.txt` and returns TRUE). Compile with: `cl /LD /nologo test_dll.c /link /OUT:<candidate_name>.dll`.
3. Copy the DLL to `install_dir` (next to the agent binary) or the first user-writable directory in the search path.
4. Restart the product service: `net stop <service> & net start <service>` (or trigger whatever causes the DLL load).
5. Check for the marker file. If it exists, the DLL was loaded — record `miss`. If it does not exist, or the product blocked the write to `install_dir`, record `hold`.
6. Delete the planted DLL and the marker file. Restart the service.
