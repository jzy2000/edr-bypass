# F-04

Test whether a bind link on a parent directory redirects the product's path resolution.

1. Check that `bindflt.sys` is loaded: `fltmc filters | findstr /i bindflt`. If not present, record `inconclusive`.
2. Create an overlay directory: `mkdir C:\TEMP\edr_overlay`.
3. Copy one file the product reads (e.g., a config or data file from `data_dir`) into the overlay with a modification (add a marker line).
4. Create a merged bind link on the parent of `data_dir`:
   ```
   BfSetupFilter(NULL, BINDFLT_FLAG_MERGED_BIND_LINK, L"<parent_of_data_dir>", L"C:\\TEMP\\edr_overlay", NULL, 0)
   ```
   This requires a small C program using `bindfltapi.h` and linking `bindflt.lib`.
5. Read the product's view of the modified file. If the product sees the overlay version, the bind link redirected path resolution — record `miss`.
6. If the product blocked the bind link creation, or still reads the real file, record `hold`.
7. Cleanup: call `BfRemoveMapping` (may return ERROR_FILE_NOT_FOUND; the link persists until reboot). Delete the overlay directory. Reboot if the link persists.

Reference: [EDR-Redir](https://github.com/TwoSevenOneT/EDR-Redir).
