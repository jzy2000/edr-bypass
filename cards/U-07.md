# U-07

Test whether the product relies solely on user-mode ETW.

1. **Patch EtwEventWrite**: in the current process, overwrite the first bytes of `ntdll!EtwEventWrite` with `xor eax, eax; ret` (return STATUS_SUCCESS without emitting).
2. Perform an action the product should detect (e.g., create a new process, allocate RWX memory, or write a known-bad file).
3. Read the product log. If the action is still detected, the product uses kernel-level ETW-TI (Microsoft-Windows-Threat-Intelligence, only accessible from PPL/kernel) or a non-ETW sensor — record `hold`.
4. If the action is invisible, record `miss`.

5. **Session disable** (requires admin): `logman query -ets` to list ETW sessions. Identify the product's session. `logman stop <session> -ets`. Perform the test action again.
6. If the action is still detected after the session is stopped, the product re-creates the session or uses another channel — record `hold`.

7. **ETW-TI tamper** (T2/T3): this is tested in K-05 (kernel-level ETW-TI provider tampering).

8. Close the test process.
