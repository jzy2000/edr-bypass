# F-08

Test whether path indirection can misdirect file protection.

1. Identify how the product resolves `data_dir`: does it read a registry key, an environment variable, or hardcode the path?
2. If it reads `HKLM\SOFTWARE\<product>\DataPath` or similar, change it: `reg add ... /v DataPath /d "C:\TEMP\fake_data" /f`.
3. Create `C:\TEMP\fake_data` and copy the product's data files there.
4. Reboot to force the product to re-read the path.
5. After reboot, attempt to write to the REAL data directory. If the product no longer protects it (protecting the fake path instead), record `miss`.
6. If the product still protects the real path, record `hold`.
7. Restore the registry value. Revert from snapshot.
