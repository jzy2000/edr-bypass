# U-05

Test whether the product relies solely on userland ntdll hooks.

1. Read a fresh copy of `ntdll.dll` from `C:\Windows\System32\ntdll.dll` (on disk, not the in-memory copy).
2. Parse the export table to find the syscall number (SSN) for `NtAllocateVirtualMemory` and `NtWriteVirtualMemory`. The stub pattern is `mov r10, rcx; mov eax, <SSN>; syscall; ret`.
3. Build a minimal C program that issues these syscalls via a hand-written stub (no `GetProcAddress`, no jump through the loaded ntdll).
4. Allocate RWX memory and write a marker pattern (e.g. `0xCC` bytes) into the current process.
5. Read the product log. If the allocation or write appears, the product has a kernel-level sensor (ETW-TI, minifilter, or callback) — record `hold`. If nothing appears, the product relied on the userland hook alone — record `miss`.
6. Free the memory and exit.

Reference: [SysWhispers](https://github.com/klezVirus/SysWhispers3), [Hell's Gate](https://github.com/am0nsec/HellsGate).
