# L-04

Test whether the driver re-verifies its binaries after an upgrade.

1. Note the current driver and companion DLL versions (S-02).
2. Trigger a product upgrade (if an upgrade mechanism exists in the lab).
3. After the upgrade writes new files but before the reboot:
   a. Replace the new driver with a test binary (same name, different content). Use bind link (F-04) if direct write is blocked.
   b. Replace the new companion DLL similarly.
4. Reboot.
5. If the driver detects the replaced files and refuses to load (BSOD with a meaningful bugcheck, or falls back to the old version), record `hold`.
6. If the replaced binaries are loaded without verification, record `miss`.
7. Restore from snapshot.
